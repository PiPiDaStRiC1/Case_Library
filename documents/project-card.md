# Карточка проекта

| Поле | Значение |
|---|---|
| Проект | LibraFlow |
| Кейс | №8, «Библиотека» |
| Тип продукта | Web-платформа и адаптивный читательский кабинет |
| Заказчик | Библиотека / сеть библиотек |
| Пользователи | Читатель, библиотекарь, администратор сети |
| Проблема | Поиск книг, проверка доступности и продление часто разнесены по разным каналам; сотрудники вручную ведут выдачу и отчётность |
| Решение | Единый каталог, личный кабинет, бронирование, продление, уведомления и рабочее место библиотекаря |
| Ценность | Меньше ручных операций, быстрее обслуживание, выше доступность фонда и прозрачнее аналитика |
| MVP | Каталог, поиск и фильтры, карточка издания, бронь, продление, выдача/возврат, уведомления, роли |
| География MVP | Одна библиотека или небольшая сеть в РФ |
| Горизонт | 12 недель до пилота, 12 месяцев до масштабирования |
| Критерий успеха | Не менее 60% операций читателя выполняются без участия сотрудника; медианное время поиска и бронирования — до 3 минут |
| Ограничения | Без собственного мобильного приложения, RFID и межбиблиотечного обмена в MVP |
| Команда | Зеленский Виктор Андреевич — team lead и backend; Кротов Артем Игоревич — frontend; Захаров Дмитрий Андреевич — backend и интеграции |

## Распределение задач

| Участник | Основная зона | Задачи |
|---|---|---|
| Зеленский Виктор Андреевич | Team Lead + backend | Архитектура, модель данных, API каталога и авторизации, бизнес-правила бронирования, code review и интеграция частей продукта |
| Кротов Артем Игоревич | Frontend | UX/UI, React-маршрутизация, каталог и личный кабинет читателя, рабочее место библиотекаря, интеграция с API и адаптивность |
| Захаров Дмитрий Андреевич | Backend + интеграции | API операций фонда, выдача/возврат, уведомления, импорт CSV, подключение внешнего API карт, тестирование backend и производительности |
