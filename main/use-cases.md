# Use Case и пользовательские сценарии

## UC-01. Найти и забронировать книгу

| Поле | Значение |
|---|---|
| Актор | Читатель |
| Цель | Забронировать доступный экземпляр |
| Предусловия | Читатель авторизован; библиотека принимает брони |
| Триггер | Пользователю нужна книга |
| Основной сценарий | 1. Открывает каталог. 2. Вводит название или автора. 3. Применяет фильтр доступности и филиала. 4. Открывает карточку. 5. Выбирает экземпляр. 6. Подтверждает бронь. 7. Получает срок хранения и уведомление. |
| Альтернативы | Нет доступных экземпляров — система предлагает очередь. Данные читателя не подтверждены — система предлагает обратиться к библиотекарю. |
| Постусловия | Бронь создана, экземпляр зарезервирован, событие записано в журнал |
| Метрика успеха | 90% успешных броней; медианное время до 3 минут |

**Пользовательский сценарий.** Анна ищет книгу с телефона по дороге в университет. Она видит доступный филиал и бронирует экземпляр, не звоня в библиотеку. В email приходит срок, до которого нужно забрать книгу.

## UC-02. Оформить выдачу

| Поле | Значение |
|---|---|
| Актор | Библиотекарь |
| Цель | Передать экземпляр читателю и зафиксировать срок возврата |
| Предусловия | Бронь активна или экземпляр свободен; сотрудник авторизован |
| Триггер | Читатель приходит за книгой |
| Основной сценарий | 1. Сотрудник находит читателя. 2. Открывает его активные брони. 3. Сканирует или выбирает экземпляр. 4. Система проверяет лимиты и просрочки. 5. Сотрудник подтверждает выдачу. 6. Статус меняется на «выдан». 7. Читателю и сотруднику показывается срок возврата. |
| Альтернативы | Есть просрочка — выдача блокируется и показывается причина. Экземпляр уже выдан — система предлагает актуализировать статус. |
| Постусловия | Выдача записана в аудит, срок возврата установлен |
| Метрика успеха | 95% операций без повторного ввода; время до 60 секунд |

**Пользовательский сценарий.** Елена работает на стойке в часы пик. Она открывает бронь по билету, видит проверку ограничений и одним действием фиксирует выдачу. Ей не нужно переносить данные в бумажный журнал.

## UC-03. Вернуть книгу

| Поле | Значение |
|---|---|
| Актор | Библиотекарь |
| Цель | Закрыть выдачу и сделать экземпляр доступным по правилам |
| Предусловия | Экземпляр числится выданным; сотрудник авторизован |
| Триггер | Читатель возвращает книгу |
| Основной сценарий | 1. Сотрудник находит выдачу по экземпляру или читателю. 2. Проверяет дату возврата. 3. Фиксирует состояние книги. 4. Подтверждает возврат. 5. Система меняет статус на «доступен» или «на проверке». 6. При наличии очереди назначает следующую бронь. 7. Отправляет уведомление следующему читателю. |
| Альтернативы | Книга повреждена — статус «на проверке», создаётся комментарий. Есть просрочка — начисление штрафа не автоматизируется в MVP, но факт отражается в отчёте. |
| Постусловия | Выдача закрыта, статус экземпляра обновлён, аудит записан |
| Метрика успеха | 99% возвратов отражаются в каталоге в течение минуты |

**Пользовательский сценарий.** Елена принимает книгу и сразу видит, что следующий читатель стоит в очереди. После подтверждения возврата система освобождает экземпляр и отправляет уведомление, не требуя отдельного списка.

## UC-04. Продлить срок пользования

| Поле | Значение |
|---|---|
| Актор | Читатель |
| Цель | Продлить книгу, если на неё нет очереди |
| Предусловия | Книга выдана читателю; лимит продлений не исчерпан |
| Триггер | До срока возврата осталось менее трёх дней |
| Основной сценарий | 1. Читатель открывает активную выдачу. 2. Нажимает «Продлить». 3. Система проверяет очередь и лимит. 4. Показывает новый срок. 5. Читатель подтверждает. 6. Система обновляет выдачу и отправляет уведомление. |
| Альтернативы | Есть очередь — продление отклоняется. Лимит исчерпан — показывается причина и дата возврата. |
| Постусловия | Срок продлён или читатель получил объяснение отказа |
| Метрика успеха | 90% решений выполняются без обращения к сотруднику |
